# oxidizr

A Rust implementation of [Structurizr](https://structurizr.com) tooling — the
"models-as-code" architecture tool for the [C4 model](https://c4model.com).
Core promise: full compatibility with the Structurizr DSL (`.dsl`) and JSON
(`.json`) workspace formats, consumable by the official tooling and back
(byte-comparable JSON where the format defines it).

Status: **Phase 1 complete (v0.1.0)** — the conversion/validation/formatting
CLI plus the `reconcile` geometry re-attach. Rendering and extra backends are
later phases (`agents/plan/README.md` is the roadmap index).

## Build

```sh
cargo build --release -p oxidizr-cli   # → target/release/oxidizr
```

The pinned nightly in `rust-toolchain.toml` is picked up automatically by
rustup; the nix dev shell (`nix develop`) adds the reference oracle, cross
toolchains and dev tooling (see `agents/plan/WORKFLOW.md`).

## Quickstart

```sh
# DSL → Structurizr JSON (`-` or omitted input = stdin, no -o = stdout)
oxidizr dsl2json workspace.dsl -o workspace.json

# JSON → JSON (normalization check; --keep-unknown preserves non-schema keys)
oxidizr json2json workspace.json -o normalized.json

# Validate workspace file(s) — format auto-detected by extension
oxidizr validate workspace.dsl workspace.json

# Reformat DSL to canonical style (in place, or CI gate with --check)
oxidizr fmt --write workspace.dsl
oxidizr fmt --check '*.dsl'

# Geometry-preserving edit loop: re-parse the edited DSL and re-attach the
# layout JSON (ids from the pre-edit export) onto it
oxidizr reconcile --dsl edited.dsl --layout layout.json -o reconciled.json
```

Global flags: `--strict` (warnings exit 1), `--quiet`, `--no-color` (also via
`NO_COLOR`), `--env`, `--version`. Exit codes: `0` success · `1` error
diagnostics (or any warning under `--strict`) · `2` usage · `3` I/O failure.
Diagnostics carry `OXZ-…` codes — see `docs/diagnostics.md`.

## Compatibility

`agents/plan/COMPAT.md` records the field-by-field JSON contract and the pinned
reference implementation that decides ambiguous behavior; deviations (and the
locked never-deviate list) live in `agents/plan/DEVIATIONS.md`. The vendored
reference corpus under `testdata/` (contract: `testdata/README.md`) is the
byte-exact source of truth for tests; goldens are generated by the official
`structurizr` application binary.

## Development

```sh
cargo xtask ci            # commit gates: fmt + clippy + test + refs
cargo xtask fuzz 60       # cargo-fuzz job mirror (nightly in CI)
cargo xtask bench         # criterion benches; cargo xtask bench cmp M7
```

Full command table, test-category rules and process: `agents/plan/WORKFLOW.md`,
`agents/plan/TESTING.md`, `AGENTS.md`.
